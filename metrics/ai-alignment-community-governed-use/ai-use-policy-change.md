## Overview

This metric is part of the [AI Alignment - Community Governed AI Use](metric-model-ai-alignment-community-governed-use.md) metrics model, which measures how clear and compliant a project's governance around AI use is.

How a community's AI policy changes over time, and how that compares to shifts happening across other projects.

Track tightening, loosening, and newly added provisions per domain (see [Consent Policy Specificity](ai-use-consent-policy-specificity.md)), so a community can see its own trajectory and where it sits relative to the wider ecosystem.

| Indicator | Implementation | Measurable now? |
| --- | --- | --- |
| Direction of change per domain | Classify each revision of a policy document as tightening, loosening, or adding a new provision, per domain | Yes |
| Trajectory over time | Read the version history of policy documents to sequence changes and see the community's own direction of travel | Yes |
| Position relative to the ecosystem | Compare a community's per-domain changes against the same classification applied to other projects | Partly |
| Enforcement mechanism | Determine whether a change is enforced automatically, case-by-case, or not yet applied | Partly |
| Vote turnout and margin | Where a change is decided by vote, record the participation rate and the result | Partly |
| Stated rationale as checkable claims | Break the reasoning given for a change into separate claims that can be evaluated on their merits rather than by outcome | Partly |

## Want to Know More?

### Data Collection Strategies

Known methods (as of this writing) for collecting data related to this metric.

| Attribute | How we'd collect it | Detectable today? |
| --- | --- | --- |
| Policy version history | Git / version history of policy documents | Yes |
| Direction of change | Classify each revision as tightening, loosening, or adding a new provision, per domain | Yes |
| Enforcement mechanism | Read the change and surrounding discussion for whether it is automated, case-by-case, or unapplied | Partial. Visible where documented |
| Vote turnout and margin | Governance records where votes are published | Partial. Only where the project publishes vote records |

### Filters

- **Direction:** tightening, loosening, new provision
- **Domain:** code contributions, notetaker / meeting bots, content, moderation actions, review, autonomous / agentic use, environmental impact, infrastructure strain, data use for training
- **Enforcement mechanism:** automatic, case-by-case, not yet applied
- **Decision method:** vote, maintainer decision, foundation-level position
- **Project size:** number of active contributors
- **Project age**
- **Governance accountable:** single maintainer, foundation, company
- **Measurable now:** yes, partly
